# AI使用经验

本文档面向新同学，介绍如何借助 AI 工具高效辅助日常开发工作。无需深入了解AI原理，重点在于掌握实用技巧与正确的使用心态。

## git安装与简单使用

Git 是目前最流行的版本控制系统，在 AI 辅助开发工作流中扮演重要角色——每次 AI 生成代码后，通过 Git 进行提交和追踪，可以随时回滚到安全的版本。

### git安装

1. 访问 [https://git-scm.com/](https://git-scm.com/) 下载对应系统的安装包
2. 安装时保持默认选项即可，注意勾选"Add Git to PATH"
3. 安装完成后，在终端执行 `git --version` 验证是否成功

### git简单使用

在 VSCode 中，左侧活动栏有"源代码管理"图标（分支图标），可以可视化完成大多数 Git 操作：

- **初始化仓库**：点击"初始化存储库"按钮，或执行 `git init`
- **暂存更改**：在更改文件旁点击 `+` 号，将文件加入暂存区
- **提交**：在消息框输入 commit message，点击"提交"按钮
- **查看历史**：推荐安装 VSCode 插件 **GitLens** 或 **Git Graph**，可视化查看提交历史

### 常用git命令

```bash
git clone <仓库地址>        # 克隆远程仓库到本地
git status                  # 查看当前工作区状态
git add .                   # 暂存所有更改
git commit -m "描述信息"    # 提交暂存区内容
git push                    # 推送到远程仓库
git pull                    # 拉取远程仓库最新内容
git log --oneline           # 简洁查看提交历史
git diff                    # 查看未暂存的差异
git checkout <branch>       # 切换分支
git branch <新分支名>        # 创建新分支
```

## AI IDE?

AI IDE（AI 集成开发环境）是在传统代码编辑器基础上深度集成 AI 能力的开发工具，能够在编写、审查、重构代码的过程中实时提供 AI 辅助。

### AI IDE

传统 IDE（如 PyCharm）专注于语法高亮、代码补全、调试等。AI IDE 在此基础上增加了：

- **对话式交互**：像聊天一样向 AI 提问或下达指令
- **代码感知**：AI 能读取当前打开的文件、光标位置、项目结构
- **自主执行**：Agent 模式下 AI 可以自主编辑文件、运行命令、完成任务

### VSCode

VSCode（Visual Studio Code）是微软开发的免费、轻量级编辑器，是目前最流行的开发工具之一。

- 通过安装插件（如 **GitHub Copilot**）即可获得 AI 能力
- 拥有丰富的插件生态，支持几乎所有编程语言
- 内置终端、Git 集成、调试器，是日常开发的全能工具
- 支持**对话模式**（Chat），**计划模式**（Plan），**自主执行模式**（Agent）
- 能够感知整个项目结构，提供上下文相关的代码建议
- 支持自定义 SKILL，扩展 AI 的专项能力
- 支持通过 MCP 连接外部工具和数据源
- 下载地址：[https://code.visualstudio.com/](https://code.visualstudio.com/)

### Antigravity

Antigravity 类似于 VSCode，集成了Google AI相关能力。

## Agent？MCP？SKILL？

### Agent

Agent（智能体）是 AI 的一种工作模式：不仅能回答问题，还能**主动规划并执行一系列操作**来完成目标。

- **普通对话模式ChatBot**：你问一句，AI 答一句，需要你手动执行代码
- **Agent 模式**：AI 自主分析任务 → 制定计划 → 逐步执行（读文件、写代码、运行命令）→ 反馈结果
- 类比：普通模式像"顾问"，Agent 模式像"实习生"，可以直接干活

> ⚠️ **注意**：Agent 模式下 AI 会真实修改文件，使用前建议先 `git commit` 保存当前状态，以便出错时回滚。

### MCP

MCP（Model Context Protocol）是一套开放协议，允许 AI 模型连接外部工具和数据源，扩展其能力边界。

- 没有 MCP：AI 只能处理你粘贴给它的文本内容
- 有了 MCP：AI 可以访问文件系统、调用 API、搜索网络等
- 理解为：MCP 是给 AI 装上了"手"和"眼睛"，让它能与真实世界交互
- 常见 MCP Server 示例：文献检索、结果文件解析、代码执行

### SKILL

SKILL 是预定义的 AI 工作指令包，用于规范 AI 在特定任务场景下的行为。

- 本质是一个包含详细说明文档（SKILL.md）的文件夹，告诉 AI"在这个任务中该怎么做、遵守什么规范"
- 例如：代码重构 SKILL、代码审查 SKILL、文档编写 SKILL
- 好处：让 AI 在重复性任务上保持一致的高质量输出，无需每次重新描述要求
- SKILL 可以复用、共享，是团队知识沉淀的重要形式

## AI的边界与局限性

在学会使用 AI 之前，需要先建立正确认知：**AI 是助手，不是权威。** 了解 AI 的局限，才能避免踩坑。

### AI幻觉（Hallucination）

AI 有时会生成**看起来完全正确、但实际上是错误的**内容，这种现象叫做"幻觉"。

- 常见表现：引用不存在的函数、编造不存在的库、给出错误的算法
- 应对方法：
  - 对 AI 生成的代码**必须自己读一遍**，理解逻辑后再使用
  - 关键逻辑要在本地运行测试，不要直接上线
  - 遇到不确定的 API，去官方文档核实

### 知识截止日期

AI 的训练数据有截止日期，对以下内容可能不准确：

- 近期发布的新框架、新版本（如最新的 JAX、NumPy、SciPy 特性）
- 已废弃或变更的 API
- 最新的安全漏洞和补丁信息

**应对**：对于新技术，优先查阅官方文档，将最新文档内容提供给 AI 作为上下文。

### 信息安全意识

以下内容**绝对不能**粘贴给 AI（尤其是在线 AI 服务）：

- 数据库密码、API 密钥、访问令牌
- 服务器地址、内网拓扑信息
- 核心数据、隐私数据

**原则**：假设你发给 AI 的所有内容都有可能被记录或泄露，据此决定是否发送。

### 何时不适合用AI

| 场景 | 原因 |
|---|---|
| 依赖实时数据 | AI 的知识有截止日期 |
| 高度安全合规要求 | AI 输出需要人工全面审查 |
| 需要创造性原创内容 | AI 倾向于给出"平均"的答案 |

## 如何使用AI IDE辅助开发

### 代码生成

AI 最直接的用途是从自然语言描述生成代码。

**使用技巧：**
- 描述清楚**输入、输出和边界条件**，而不仅仅说"帮我写个函数"
- 告知使用的语言版本和依赖库
- 生成后**必须阅读代码**，理解其逻辑再使用

**示例提示词：**
> 用 Python 3.11 和 JAX 写一个函数，输入四节点平面应力单元的节点坐标、位移向量和材料参数，计算单元刚度矩阵和内力向量。要求使用 `jax.numpy`，并支持 `jit` 加速。

### 代码补全

在 AI IDE 中，AI 会根据当前光标位置和上下文，实时预测并补全代码。

- 按 `Tab` 键接受补全建议
- 补全不合适时直接忽略，继续输入
- 补全对**重复性、模式化**的代码效果最好（如遍历、异常处理、配置读取）

### 代码审查

将需要审查的代码粘贴给 AI，让其发现潜在问题。

**可以让 AI 检查：**
- 潜在的 Bug 和边界条件
- 性能问题（如循环内重复装配矩阵、频繁进行主机与设备数据拷贝）
- 代码可读性和命名规范
- 是否符合特定的编码风格

**示例提示词：**
> 请审查以下 Python/JAX 代码，找出潜在的 bug、性能问题和不符合 PEP8 规范的地方，并给出修改建议，重点检查是否存在不必要的 Python 循环、`jit`/`vmap` 使用不当或频繁的数据拷贝。

### 代码重构

让 AI 在不改变功能的前提下，改善代码结构。

- **拆分大函数**：要求 AI 将超过50行的函数拆分为多个小函数
- **提升可读性**：改善变量命名、添加注释
- **消除重复**：提取公共逻辑为独立函数或类
- 重构后务必运行已有测试，确保行为未变

### Debug辅助

遇到报错时，将**完整的报错信息和堆栈追踪**提供给 AI，快速定位原因。

**提供给 AI 的信息应包含：**
1. 完整的错误信息（不要只截图，复制文本）,有的AI可以追踪终端输出，可以不用复制
2. 触发错误的代码片段
3. 你期望的行为是什么

**示例提示词：**
> 我的 JAX 代码在装配有限元刚度矩阵时运行时报以下错误，请帮我分析原因并给出修复方案：
> `[粘贴完整错误信息]`
> 相关代码如下：
> `[粘贴相关代码]`

### 单元测试生成

让 AI 为已有函数自动生成单元测试，提升代码质量。

- 提供函数代码，要求 AI 生成覆盖正常情况、边界情况和异常情况的测试
- 指定测试框架（如 `pytest`、`unittest`）
- 检查生成的测试是否真的能捕捉到错误

### 技术选型与方案咨询

在开始一个新功能前，可以先问 AI：

> 我需要在 Python 里实现一个 JAX 加速的有限元求解器，有哪些常见的技术方案？各有什么优缺点？

AI 能快速给出多种方案对比，帮助你缩小选择范围，再结合官方文档做最终决策。

## 提示词工程

提示词工程（Prompt Engineering）是指通过优化向 AI 提问的方式，从而获得更准确、更有用输出的技巧。好的提示词能让 AI 事半功倍，差的提示词会让 AI 答非所问。

### 提示词工程概念

提示词不只是"问题"，它包含了你给 AI 的所有信息和指令。AI 的输出质量很大程度上取决于提示词的质量。

核心原则：**垃圾输入，垃圾输出（Garbage In, Garbage Out）**。提示词越清晰具体，输出越准确可用。

### 如何清晰描述需求

一个高质量的提示词应包含以下要素：

| 要素 | 说明 | 示例 |
|---|---|---|
| **背景（Context）** | 当前项目/场景是什么 | "这是一个基于 Python 和 JAX 的有限元求解器" |
| **目标（Goal）** | 想要 AI 做什么 | "帮我实现四节点平面应力单元的刚度矩阵装配" |
| **约束（Constraints）** | 限制条件和要求 | "使用 JAX，并支持 `jit` 加速，不依赖商业有限元库" |
| **示例（Examples）** | 期望的输入输出格式 | "输入格式如：`{'coords': jnp.ndarray, 'disp': jnp.ndarray, 'material': {'E': ..., 'nu': ...}}`" |

**改进示例：**

❌ 差：`帮我写一个四节点平面应力单元的刚度矩阵函数`

✅ 好：`用 Python 3.11 和 JAX 实现一个四节点平面应力单元的刚度矩阵函数，接收节点坐标、位移向量和材料参数，返回单元刚度矩阵和内力向量。要求支持 `jit`，并能直接用于批量装配。`

### 常用提示模式

- **角色扮演**：让 AI 进入特定专家视角，提升答案质量
  > "你是一名有10年经验的计算力学和 Python/JAX 工程师，请帮我审查以下代码..."

- **Chain-of-Thought（思维链）**：要求 AI 先分析再给出答案，减少直接给出错误答案的概率
  > "请先分析这个有限元装配在 `jit` 下报 shape mismatch 的根本原因，然后再给出解决方案"

- **迭代优化**：不要每次从头描述，基于 AI 的上一次输出继续追问
  > "你刚才的方案在大规模网格和 GPU 上可能有性能问题，请针对 JAX 的向量化和内存布局优化"

- **格式控制**：明确要求输出格式
  > "请以 Markdown 表格格式输出不同本构积分方案的对比结果" / "只输出代码，不需要解释"

### 上下文管理

AI 对话窗口有 Token（字数）限制，单次对话的上下文不是无限的：

- **Token 耗尽**：当对话过长时，AI 会"忘记"早期内容，导致回答前后矛盾
- **拆分对话**：将大任务拆分为多个小任务，每个任务开一个独立对话
- **新开对话时机**：
  - 当前话题已完成，开始一个全新的任务
  - 感觉 AI 开始"犯糊涂"，答非所问
  - 上下文超过约 20 轮对话

**技巧**：在新对话开始时，提供必要的背景信息，帮助 AI 快速理解上下文。

### 中英文提示词的差异

| | 中文提示词 | 英文提示词 |
|---|---|---|
| **优点** | 表达自然，快速输入 | 技术术语更精准，部分模型处理效果更好 |
| **适用场景** | 日常开发任务、需求描述 | 涉及专业技术概念、需要精确指令 |
| **建议** | 中文描述需求，英文标注技术术语 | — |

实践建议：用**中文写需求和约束**，技术名词保持英文原文（如"使用 async/await 实现异步处理"）。

## markdown使用

Markdown 是一种轻量级标记语言，使用纯文本编写，渲染后格式清晰美观。在 AI 辅助开发工作流中，Markdown 是记录思路、编写文档、与 AI 协作的核心格式。

### markdown基础语法

```markdown
# 一级标题
## 二级标题
### 三级标题

**加粗**  *斜体*  `行内代码`

- 无序列表
- 第二项

1. 有序列表
2. 第二项

> 引用块

\```python
# 计算力学示例：用 JAX 计算单元应变能
import jax.numpy as jnp

def strain_energy(stiffness, displacement):
    return 0.5 * displacement @ stiffness @ displacement
\```

| 单元 | 应变能 |
|-----|-----|
| 四节点单元 | `12.8` |
```

### AI工作流文件

在 Antigravity 等 AI IDE 中，Markdown 文件可以作为 AI 的任务说明文件（如 SKILL.md、Plan 文件等）。AI 能读取这些文件，理解任务背景和要求，从而更准确地执行。

- 工作流文件通常描述：任务目标、执行步骤、约束条件、输出格式
- 放置在项目根目录或 `.ai/` 文件夹中，方便 AI 引用

### 过程记录

使用 Markdown 记录开发过程中的关键决策和踩坑经验：

- 为什么选择某个方案（而不是其他方案）
- 遇到了什么问题，如何解决的
- 下次应该注意什么

这些记录既是个人知识库，也可以作为上下文提供给 AI，帮助它更好地理解项目历史。

### 实施方案编写与评审

在开始复杂任务前，先用 Markdown 写出实施方案，再让 AI 或自行评审：

```markdown
## 实施方案：JAX 有限元求解器重构

### 目标
将现有的循环式单元装配迁移到 JAX 向量化实现

### 方案设计
1. 提取单元刚度矩阵与内力计算函数
2. 将网格装配改为 `vmap` 和 `jit` 兼容实现
3. 为边界条件和后处理补充测试

### 影响范围
- 单元装配模块
- 材料本构与边界条件处理

### 回滚方案
若出现问题，可通过 git revert 回滚到 commit [hash]
```

## AI开发工作流

将 AI 融入完整的开发流程，而不是零散地使用 AI 回答问题。以下是一套经过实践验证的 AI 辅助开发工作流。

### 需求分析

拿到需求后，先和 AI 对话，澄清需求细节：

- 向 AI 描述需求，让它**提出可能遗漏的边界情况和潜在问题**
- 让 AI 帮助将模糊需求转化为具体的功能点列表
- 确认技术约束：使用的框架、性能要求、兼容性要求

> 示例：*"我需要实现一个二维线弹性有限元后处理功能，请帮我列出需要考虑的所有细节，包括网格数据结构、边界条件、数值稳定性和性能"*

### Plan模式

在 AI IDE 中使用 Plan 模式（规划模式），让 AI 先**制定详细的执行计划**，而不是直接开始修改代码：

- AI 会分析现有代码结构
- 列出需要修改的文件和具体步骤
- 预估影响范围和潜在风险
- 此阶段 AI **不会实际修改任何文件**

### Plan评审

在 AI 开始执行前，**仔细阅读和评审 Plan**：

- 检查计划是否符合预期
- 确认修改范围是否合理（有没有遗漏或多余的修改）
- 发现计划中的逻辑错误，及时纠正
- 如有问题，在此阶段修改计划，成本最低

> ⚠️ **不要跳过评审**，让 AI 直接执行未经确认的计划可能导致大范围的错误修改。

### Agent执行

确认 Plan 无误后，让 AI Agent 执行计划：

- Agent 会按计划逐步修改文件、运行命令
- 执行过程中观察 AI 的操作，异常时及时中断
- AI 执行完成后会给出执行摘要

### 多轮迭代

AI 第一次给出的方案不一定是最好的，通过多轮对话逐步优化：

- **追问细节**："这个方案在并发量大时会有什么问题？"
- **要求解释**："请解释第3步为什么要这样处理"
- **提出反例**："如果输入为空列表，你的方案是否还正确？"
- **要求替代方案**："有没有不依赖外部库的实现方式？"

### code review

AI 生成的代码提交前，必须进行人工审查，重点关注：

| 检查项 | 说明 |
|---|---|
| **逻辑正确性** | 是否真的实现了预期功能 |
| **边界条件** | 空值、极大值、特殊字符等极端情况 |
| **错误处理** | 是否有合适的异常捕获和错误提示 |
| **安全性** | 是否存在 SQL 注入、路径遍历等安全问题 |
| **可读性** | 命名是否清晰，逻辑是否易于理解 |
| **性能** | 是否存在明显的性能问题（如循环内重复装配矩阵、频繁进行主机与设备数据拷贝）|

### 文档总结

开发完成后，让 AI 帮助整理文档：

- **公式与代码对应关系**：将算法公式和实现代码对应说明，方便后续维护
- **接口文档**：根据代码自动生成 API 文档
- **设计决策记录**：记录为什么采用当前方案，而不是其他方案
- **使用说明**：新成员快速上手的指南

### git diff与变更审查

提交前使用 `git diff` 审查所有变更，确保没有意外修改：

```bash
git diff              # 查看未暂存的修改
git diff --staged     # 查看已暂存的修改（即将提交的内容）
git diff HEAD~1       # 与上一次提交对比
```

也可以将 `git diff` 的输出提供给 AI，让它帮你审查本次变更是否符合预期。

### git commit

每完成一个功能点或修复一个问题，就进行一次提交：

- 保持小步提交，每次提交只做一件事
- 提交信息要清晰描述做了什么（借助 AI 生成）
- AI 辅助开发时，建议在 commit message 中标注关键决策

### commit message编写

良好的 commit message 是项目历史的说明书，可以借助 AI 来生成：

**格式规范（Conventional Commits）：**
```
<类型>(<范围>): <简短描述>

[可选的详细说明]
```

**常用类型：**
- `feat`: 新功能
- `fix`: Bug 修复
- `refactor`: 代码重构
- `docs`: 文档更新
- `test`: 测试相关

**让 AI 生成 commit message 的方法：**
> 以下是本次修改的 `git diff` 内容，请帮我生成一条符合 Conventional Commits 规范的 commit message：
> `[粘贴 git diff 内容]`

### 推荐SKILL

SKILL 是可复用的 AI 工作指令包，以下是一些实用 SKILL 的获取方式：

- **查找已有 SKILL**（find-skills: https://skills.sh/vercel-labs/skills/find-skills ）: 我想要进行代码重构，找到适合当前任务的 SKILL
- **创建自定义 SKILL**（skill-creator: https://skills.sh/vercel-labs/skills/skill-creator ）: 针对团队的重复性任务，将最佳实践固化为 SKILL，沉淀知识、统一标准

**SKILL 文件基本结构：**
```
my-skill/
├── SKILL.md          # 技能说明文件（必须）
├── examples/         # 示例文件（可选）
└── resources/        # 参考资源（可选）
```

通过积累和共享 SKILL，团队可以把经验固化为可复用的资产，让每个人都能享受最佳实践带来的效率提升。
