# 专利写作技能（中文发明专利/软件著作权）

## 目标
将用户的技术方案整理为结构完整、术语统一、可直接进入后续法务加工流程的专利草案，避免空泛描述、逻辑断裂与格式错误。

## 适用输入
- 已有专利草案（markdown/docx/纯文本）
- 论文、项目报告、实验记录、代码说明
- 用户口述的发明点、对比方案、应用场景

若输入信息不足，先补齐最小信息集，再开始正文撰写。

## 最小信息集（缺一则先追问）
1. 发明名称（暂定名可接受）
2. 解决的核心技术问题（1-4条）
3. 技术方案关键步骤或模块
4. 至少1个可量化效果（速度、精度、稳定性、成本等）
5. 应用对象与边界条件

## 输出结构（默认模板）
按以下标题顺序输出：
1. 基本信息
2. 所属技术领域
3. 背景技术
4. 本发明创造要解决的技术问题
5. 本发明创造的技术方案
6. 本发明创造的效果和优点
7. 附图说明
8. 具体实施方式
9. 检索关键词及可替代表述

如用户已给定章节编号，保持其编号体系。

## 模板文件（优先使用）
- 模板路径：assets/patent_draft_template.md
- 触发本技能后，优先按模板填空输出，不要从空白结构重新组织。
- 若用户仅要求补写某一章，只提取模板对应章节进行填充。
- 若用户给出固定标题或编号，以用户要求覆盖模板默认项。

## 写作规则
1. 先问题后方案：每个技术问题都要在技术方案中有对应解决手段。
2. 强调区别点：每个核心特征都要写“区别于现有方法”。
3. 强调技术效果：每个核心特征都要写“技术效果”，且尽量可量化。
4. 术语统一：同一概念只用一个主名称，首次出现可给别名。
5. 避免结论先行：先给输入、处理、输出，再给效果。
6. 实施例可复现：参数、工况、边界条件、停止准则要可执行。

## 表格与公式规范（重点）
1. Markdown 表格每一行必须是单行，不可把单元格内容拆成多行。
2. 表格中的数学符号使用行内公式形式，如 $C_{11}$、$\Delta D_{\max}$。
3. 禁止在表格中插入独立块公式（即 $$...$$ 单独成行），否则会导致渲染断表。
4. “检索关键词及可替代表述”优先使用两列表格：关键词 | 可替代表述。

## 工作流程
1. 读取并复制模板 assets/patent_draft_template.md 作为起稿骨架。
2. 提取发明骨架：技术问题、核心特征、流程步骤、指标。
3. 构建章节映射：问题-手段-效果三联映射表。
4. 按模板填空生成技术方案：按“输入-处理-输出”写步骤，必要时给公式。
5. 按模板填空生成实施例：给参数表、控制参数、结果对比。
6. 结构化校验：
   - 编号连续
   - 术语一致
   - 表格合法
   - 公式可读
   - 每个问题有对应方案与效果

## 质量自检清单（输出前必须逐项检查）
- 是否存在“只讲背景不讲区别点”
- 是否存在“步骤缺输入或缺输出”
- 是否存在“效果不可验证”
- 是否存在“表格断裂（空行、块公式插入表格）”
- 是否存在“术语混用（同物多名）”

## 专利改写场景（基于已有专利写新专利）
当用户要求“基于已有专利写新的”，执行以下策略：
1. 保留结构，不复用原表述句式。
2. 先抽象可迁移方法论，再替换应用对象、约束条件、关键参数域。
3. 至少重写以下部分：
   - 技术问题定义
   - 核心技术特征标题与阐述路径
   - 实施例参数与结果组织方式
4. 输出中显式给出“新旧方案差异点”列表，便于后续检索与规避重合。

## 默认输出格式偏好
- 使用清晰标题与短段落。
- 参数与术语优先表格化。
- 对长流程优先使用 S1/S2/... 步骤编号。
- 在不影响准确性的前提下，优先给可直接粘贴到 markdown 的版本。
